# Requirements Table

| ID | Type | Description | Priority | Acceptance Criteria | Rationale |
|---|---|---|---|---|---|
| FR-001 | Functional | The system shall allow student teams to create project profiles containing project title, abstract, demo video link, and verified GitHub repository URL. | High | Pass: A valid project profile is created and published after successful validation. Fail: Invalid or incomplete project details are accepted. | Enables student teams to present their projects in a centralized showcase. |
| FR-002 | Functional | The system shall allow student teams to submit project multimedia artifacts and project details for the showcase. | High | Pass: A complete submission is successfully stored and available for review. Fail: An incomplete submission is accepted. | Provides a structured process for project submission. |
| FR-003 | Functional | The system shall allow panel judges to evaluate submitted projects using digital grading rubrics. | High | Pass: A judge can assign scores using the provided rubric and submit the evaluation. Fail: Scores outside the permitted range are accepted. | Enables standardized and digital project evaluation. |
| FR-004 | Functional | The system shall allow public users to vote for showcase projects while applying anti-sybil protections. | High | Pass: A valid user can cast an eligible vote and duplicate voting attempts are rejected. Fail: The same user can repeatedly vote for the same project. | Ensures fair and reliable public voting. |
| FR-005 | Functional | The system shall display project rankings and leaderboard results based on judge scores and public votes. | Medium | Pass: The leaderboard correctly reflects updated scores and votes. Fail: Incorrect rankings are displayed. | Allows stakeholders to view project performance and competition results. |
| NFR-001 | Non-Functional - Performance & Security | The public voting and leaderboard calculations shall update in real-time with an API response latency under 300 ms. | High | Pass: Benchmarking tests confirm response latency below 300 ms under simulated peak load while maintaining security standards. | Ensures responsive voting and accurate leaderboard updates. |
| NFR-002 | Non-Functional - Usability | The system shall provide a simple and consistent interface that allows users to complete common tasks with minimal confusion. | Medium | Pass: Representative users can submit, evaluate, or vote for projects without encountering usability errors. Fail: Users are unable to complete common tasks without assistance. | Improves accessibility and ease of use for students, judges, and public users. |
